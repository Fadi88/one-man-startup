# Legal playbook

**Not legal advice.** These are the founder's positions, which the `legal` agent applies. Each
position: the standard, what is acceptable, and what escalates to the founder and to counsel.
Setup writes the first version from the founder's answers; only the founder changes it.

| Topic | Standard position | Acceptable | Escalate when |
|---|---|---|---|
| Personal data collected | Only what a feature needs, named in its spec | An extra field with a written reason | Sensitive categories (health, biometrics, children, finances) |
| Retention | Deleted when the account is deleted, or after (setup fills) | Longer where a law requires it, cited | Any indefinite retention |
| Consent for analytics and marketing | Opt in where the region requires it, never pre-ticked | Legitimate interest where a pack allows it, cited | Any tracking across sites or apps |
| Processors and sub-processors | Listed in the privacy policy, with a DPA | | A processor outside the users' regions (cross-border transfer) |
| AI features | Users are told when they interact with AI or see generated content | | Automated decisions with legal or similar effects on people |
| Marketing claims | Only claims the product can show | | Health, financial, environmental or comparative claims |
| Refunds and cancellation | As easy to cancel as to sign up | | Any region with a statutory cooling-off period not yet handled |
| Rebuilding an existing app | Nothing of the original's own is copied: name, logo, icons, images, text, code | Similar features, built and worded from scratch | A name or look users could mistake for the original's; the original's terms forbid what we did to study it |
| Business customers | Standard terms and DPA | Small edits logged in `p1-closed-decisions.md` | Liability caps, indemnities, audits, data location demands |
