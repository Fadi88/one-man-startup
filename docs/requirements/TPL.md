# TPL: the template itself

The rows that keep this template honest. A project created from it keeps the rows about how the
template works, and adds its own area files beside them; setup removes the rows about the
template's own pages (`tools/clean_template.py`).

| ID | Requirement | Status |
|---|---|---|
| TPL-1 | Every file in `agents/` has frontmatter with `name`, `description`, `tier`, `access`, `skills` and `hands_off_to`, its `name` matches the file name, `tier` is deep, standard or fast, and `access` lists only read, web, run, check, edit and delegate, with delegate on the orchestrator alone. | T |
| TPL-2 | Every skill an agent lists exists in `skills/`, and every agent named in `hands_off_to` exists in `agents/`. | T |
| TPL-3 | Every folder in `skills/` has a `SKILL.md` whose `name` matches the folder and whose `description` says when to use it, and every skill file named by path in an agent or skill exists. | T |
| TPL-4 | The team table in `docs/TEAM.md` (not `AGENTS.md`, so adding an agent costs `AGENTS.md` nothing) lists every agent in `agents/` and no other, each with a one-line job and a link to its own file, and `project.toml [team] enabled` names only agents that exist. | T |
| TPL-5 | `AGENTS.md`, each agent file and each `SKILL.md` stay inside their size budgets, so loading them stays cheap. | T |
| TPL-6 | The tool files generated by `tools/sync_adapters.py` match their sources in `agents/` and `skills/`; a hand edit to a generated file fails the sweep. | T |
| TPL-7 | The commit-msg hook refuses the characters banned in `project.toml [style]`, with either line ending, and accepts any other message, including co-author trailers, tool bylines and session links. | T |
| TPL-8 | No tracked text file contains a character banned in `project.toml [style]`. | T |
| TPL-9 | Requirement rows are well formed, ids are unique, status letters are T, M, U, X or n/a, every T row is named by a check, and every id cited in a check exists. | T |
| TPL-10 | The row counts in `docs/REQUIREMENTS.md` are computed by `tools/checks/req_check.py --fix`, never typed. | T |
| TPL-11 | Every running or planned entry in `docs/EXPERIMENTS.md` has a hypothesis, a prediction, a "wrong if" and a read date. | T |
| TPL-12 | Every region pack in `docs/legal/regions/` opens with the not-legal-advice line and carries an "As of" date and a sources list. | T |
| TPL-13 | `tools/run_all.py` exits 0 when green, 2 when every failing line is registered in `tools/known_red.json`, and 1 on a new red, an overdue recheck or a broken check. | T |
| TPL-14 | (A-1) The setup interview writes `project.toml`, the region packs and the first decisions, and leaves the sweep green. | M |
| TPL-15 | (A-2 to A-5) The template works from Claude Code, Codex, Gemini CLI and Cursor: each reads `AGENTS.md`, and the native agents and skills are generated where the tool supports them. | U |
| TPL-16 | Every open assumption in `docs/ASSUMPTIONS.md` has a way to confirm it and a confirm-by date that has not passed, and every settled one says what settled it. | T |
| TPL-17 | Text copied verbatim from upstream (the Karpathy guidelines, Anthropic's frontend-design skill) stays unchanged, pinned by hash in `tools/lib/verbatim.py`, so it can be compared with upstream. | T |
| TPL-18 | The README opens with the premise, building a software startup without writing code, says plainly that this is not vibe coding, and shows each step of the workflow beside the established software practice it follows. | M |
| TPL-19 | The README shows the template's architecture as a diagram (the founder, the AI tool, the instructions it reads, the files it writes and the checks it runs), and every diagram in `docs/images/` reads in both light and dark themes. | M |
| TPL-20 | The template has a landing page built from `site/` and published to GitHub Pages by `.github/workflows/pages.yml`, which copies the diagrams from `docs/images/` at build time, and a 1280 by 640 social preview image rendered from `docs/images/social-preview.svg`. | M |
| TPL-21 | `docs/images/demo.svg` replays the recorded setup dry run with every line quoted word for word from its transcript, and any still frame of it shows the whole exchange. | M |
| TPL-22 | For every feature and bet, `researcher` writes `docs/work/<id>/research.md` before the first grilling round: five to eight similar products, each with what it does, its price and a dated source, and suggestions that the grilling puts to the founder as options with a recommendation. | U |
| TPL-23 | For every feature and bet, `feasibility` writes `docs/work/<id>/feasibility.md` after grilling and before the founder confirms the spec: a go, go with changes or no-go verdict, each part's risk with a dated source, running cost at 1x and 10x usage, and the blockers. Recommended changes go back to the founder. | U |
| TPL-24 | `reviewer` reviews each spec, design and developer diff before it is handed on and writes `docs/work/<id>/review.md` with blocking findings and suggestions; it never edits the work, and nothing moves on while a blocking finding is open unless the founder accepts it in writing. | U |
| TPL-25 | `dashboard` builds a private, sign-in only dashboard for the founder with each figure traced to one source; for a product that calls AI or another paid service, it shows usage and spend per user, per feature and in total against the caps and the budget, and offers the founder's chosen controls, each confirmed, audited and reversible. | U |
| TPL-26 | The project manager is the founder's single point of entry: `AGENTS.md` makes every session answer as `orchestrator`, which starts setup by itself on a new project (after checking Git and Python), and no guide asks the founder to type a command or name an agent. | M |
| TPL-28 | `project.toml [owner] level` is one of non-technical, basics or technical; setup asks for it, and grilling asks for it first whenever it is unset. | T |
| TPL-29 | Every question, grilling round, approval request and document the founder reads is worded for their level as `skills/founder-voice/` describes; for a non-technical founder it carries no technical terms. | M |
| TPL-30 | On the first setup, `tools/clean_template.py` removes the template's own content from the new project (its decisions, rejected ideas, experiments, assumptions, landing page, examples, marketing diagrams and README, replaced by one for the project) on the founder's go, keeps the template's MIT notice in `docs/licenses/one-man-startup.txt`, and the project's sweep stays green afterwards. | T |
| TPL-31 | Setup asks the founder which licence the product's code is under, explains each option and what it means for the business from `skills/setup/licences.md` (sourced and dated, flagged as not legal advice), records the choice in `project.toml [product] licence` and writes `LICENSE` from the official text. | U |
| TPL-27 | `docs/START-HERE.md` takes a non-technical founder from nothing to the first message to the project manager with Claude Code in a terminal, typing only the install line and `claude`, with real screenshots in `docs/images/start/`, and is linked first from the README and the landing page. | M |
| TPL-32 | When `qa` writes the verdict ROLLBACK for a major error live (the main flow broken, data lost, corrupted or exposed, wrong payments, spend far above its caps), the orchestrator starts `rollback` before other work; it restores the last good version from the release's written plan on the founder's go, proves the main flow works again, and writes `docs/work/<id>/rollback.md`. | U |
| TPL-33 | `debugger` takes every bug whose fix failed three times, every incident after a rollback and every failure nobody can explain, and writes `docs/work/<id>/debug.md` with the reproduction, the measurements, the cause with its evidence and a test that fails for that reason. | U |
| TPL-34 | For any feature where the product's AI acts, decides or produces something for users, `agentic-workflow` writes `docs/work/<id>/agentic.md` before the architect's design: the simplest shape that works, each step's model and limits, tools with the narrowest permission, guardrails and human approvals, failure handling, evals with the founder's pass bar, and the cost per run from dated pricing. | U |
| TPL-35 | `web-dev`, `android-dev`, `ios-dev` and `desktop-dev` build the platforms that `project.toml [stack] platform` includes, test first, from `product-designer`'s `ux.md` and the API contract, and raise anything they cannot build as drawn instead of redesigning it; store accounts, signing and each release to users are the founder's steps. | U |
| TPL-36 | For every feature users will see, `product-designer` writes `docs/work/<id>/ux.md` before any developer builds it: one design system for every platform, every state of every screen, the final interface copy, accessibility to WCAG 2.2 AA unless the founder set another bar, and a section per platform saying where that platform's own conventions win. | U |
| TPL-37 | On every review, `reviewer` checks the work against `project.toml [team] enabled` and suggests, under "Team" in `review.md`, any agent the project now needs (a new platform, AI that acts for users, payments, personal data, a first release, a kind of finding that keeps coming back) or a role no agent covers, never blocking and never one already declined without a new fact; the orchestrator puts each to the founder, and a yes reruns setup's team question. | U |
| TPL-38 | The README puts the promise, a start link and the recorded demo in its first screen, then the journey, team and approval diagrams before the long tables, with no badges or emoji; every image it shows uses one flat style (paper, ink and one deep blue accent, no gradients, glows or shadows) in both light and dark themes. | M |
| TPL-39 | Setup's first step runs `tools/repo_visibility.py`; when the repository is public on GitHub it tells the founder that anyone can read it, recommends private with the steps, and records a public repository the founder keeps in `p1-closed-decisions.md`. | M |
| TPL-40 | Setup's budget question asks what the founder spends each month on the AI tools that build the product, and says it is not the cost of AI inside the product; `project.toml [budget]` says the same. | M |
| TPL-41 | Setup asks whether the product is a new idea or a generic version of an existing app; `project.toml [product] origin` is unset, new or rebuild, and a rebuild names the app in `based_on`, has `researcher` map its public features first, adds a `LAUNCH` row that nothing of the original's own is copied, and adds the playbook row to `legal`'s launch review. | M |
| TPL-42 | An agent whose own file or one of its skills tells it to run a `python tools/` command has run or check access. Check access runs only the template's read-only checkers (`link_check.py`, `run_all.py`, `repo_visibility.py`, `checks/*_check.py`) with plain arguments; in Claude Code a hook generated into the agent (`tools/lib/check_only.py`) blocks every other command. `legal` runs the link checker on the region packs itself. | T |
